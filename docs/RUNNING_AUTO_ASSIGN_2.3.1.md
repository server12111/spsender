# Новые аккаунты в запущенной рассылке — 2.3.1

20 ноября 2026. Назначение нового аккаунта теперь отдаёт приоритет рассылкам со статусом `RUNNING`.

- Если запущена одна рассылка, аккаунт назначается в неё сразу при сохранении. Черновики, приостановленные и остановленные рассылки не требуют лишнего выбора.
- Если запущено несколько рассылок, интерфейс предлагает выбор только между ними.
- Если запущенных нет, сохранено прежнее поведение: единственная существующая рассылка выбирается автоматически, между несколькими предлагается выбор, без рассылок аккаунт остаётся свободным.
- Явно указанная рассылка при ручном назначении имеет приоритет.

Выбор и назначение выполняются внутри той же транзакции SQLite, что сохранение аккаунта. Назначение использует существующее формирование пары: сначала дополняется неполная пара этой рассылки, затем создаётся новая. API-закрепление сохраняется в той же транзакции. Поведение применяется к добавлению через номер и импорту сессии, поскольку оба пути используют общий метод сохранения.

После сохранения интерфейс показывает сообщение об автоматическом добавлении и название запущенной рассылки. Это немедленное включение в состав рассылки, а не обход подготовки: 24 часа тишины, прогрев, готовность пары, фиксированные смены, права чатов и FloodWait продолжают действовать.

Проверки: [test_running_auto_assign.py](../tests/test_running_auto_assign.py), 7 случаев. До реализации пять случаев упали, два уже проходили. Проверены наличие черновика/паузы/остановленной кампании рядом с работающей, дополнение пары, несколько работающих кампаний, явное назначение, свободный пул, API-закрепление и отсутствие отправок в тихий период.

Полный результат: **472 passed за 76,54 с**, [JUnit XML](running-auto-assign-test-results.xml). Ruff и smoke прошли. Настоящие подключения, коды входа и отправки при проверке не выполнялись. Рабочие `.env`, база, сессии и журналы не изменялись, бот остаётся выключенным. Новая миграция не нужна, схема остаётся 013.
