# Проверка перед публикацией 2.0.5

Управлять ботом могут только числовые Telegram ID из переменной `ADMIN_IDS`. Telegram-группы и анонимные сообщения игнорируются. Личный чат должен принадлежать тому же разрешённому пользователю. Проверка применяется к `/start`, вводу текста, файлам и callback-кнопкам; доменные операции дополнительно проверяют ID. Записи в старой таблице `admins` самостоятельно доступа не дают. Без заданного `ADMIN_IDS` Telegram-runtime не запускается. В публичном примере ID не заполнен.

Исправления, найденные при проверке:

- Анонимные сообщения могли приводить к обращению к отсутствующему `from_user`. Теперь отсекаются до обработки.
- Ответ Telegram при обновлении меню мог завершиться ошибкой после уже выполненной команды. Ошибка теперь попадает в диагностику, команда не выполняется повторно.
- Правило `data/` в `.gitignore` исключало не только рабочие данные, но и `app/data/greetings.json`. Правило ограничено корневой папкой `/data/`; встроенный пул отслеживается Git.

Добавлены совместимый запускатель `main.py`, `requirements.txt` и обновлённое Docker-окружение для нового приложения. Старые web/API/платёжные компоненты другого бота в новую рабочую ветку не входят. Предыдущий коммит сохраняется отдельной веткой перед заменой.

Проверки доступа покрывают чужого пользователя, чужую кнопку, загрузку файла без доступа, ID старого администратора в БД, сообщения в группах, анонимные обновления, несоответствующий личный чат и неправильные значения ID. Также проверяется ошибка сети при обновлении меню после остановки рассылки.

Полный локальный результат: **170 тестов успешно, 19,85 с**, файл `admin-release-test-results.xml`. Все тесты используют имитацию Telegram; реальная отправка и запуск бота не выполняются. Также прошли Ruff, компиляция, smoke, миграции 001–006, проверка целостности SQLite, зависимостей и совместимого `main.py`. Docker-образ локально не запускался. GitHub Actions настроен на Windows/Linux и Python 3.11/3.13, результаты облачного запуска следует смотреть в репозитории.

При публикации исключаются `.env`, сессии, SQLite-файлы, рабочие медиа/журналы, виртуальное окружение и материалы аудита исходного архива. Реальные токены в Git не сохраняются.
