# Проверка и исправления FE AutoSender 2.0.6

Дата: 03.11.2026. База проверки: опубликованный коммит `da78fef` версии 2.0.5.
Исходный архив не изменялся. Бот не запускался; Telegram API заменён тестовыми клиентами.

## Исправленные ошибки

| № | Ошибка | Исправление |
|---|---|---|
| 1 | Невалидное регулярное выражение обрывало все подходящие входящие события | Проверяемое выражение для английских и русских сообщений; тесты проходят через настоящий обработчик адаптера |
| 2 | Исчерпавшая повторы цепочка ЛС оставалась ACTIVE и блокировала собеседника | Известная ошибка переводит цепочку в FAILED и освобождает резерв. Новый входящий запрос, явное возобновление или исправление шаблона продолжают неподтверждённый шаг |
| 3 | После удаления/переноса аккаунта его цепочка блокировала замену | Отмена его незавершённых цепочек и освобождение резервов в той же транзакции |
| 4 | После удаления рассылки не открывались карточки свободных аккаунтов | Интерфейс и текущая статистика исключают пары удалённых рассылок. Исторические пары сохранены: их неопределённые операции всё ещё блокируют небезопасное переназначение |
| 5 | Повторное добавление удалённого Telegram ID падало по UNIQUE | Удалённая запись освобождает Telegram ID, новая получает отдельный ID и новые 24 часа тишины. Добавление действующего дубликата выдаёт понятную ошибку |
| 6 | Настройка числа пар за цикл игнорировалась | Планировщик читает сохранённое значение из SQLite перед циклом |
| 7 | Перенесённый аккаунт получал CHECK/JOIN, связанный со старой парой | Новое задание получает отдельный ключ при смене контекста. Исторические попытки не перепривязываются |
| 8 | Отзыв разрешения на вступление не останавливал старый JOIN | Очередь обновляется при изменении разрешения; guard проверяет актуальное разрешение и для уже взятого задания |
| 9 | Кнопка списка чатов пары индексировала coroutine до await | Список извлекается из завершённого результата |
| 10 | Старая кнопка редактирования меняла другой шаблон после удаления предыдущего | Список и версия читаются одним снимком; кнопка связана с версией, устаревшее редактирование отклоняется |
| 11 | Явная блокировка собеседником классифицировалась как UNKNOWN всей пары | Известные отказы получателя классифицируются отдельно, сообщение не считается отправленным; остальные отправки пары продолжаются |
| 12 | Ошибка назначения оставляла частично созданную рассылку | Создание, назначения и квитанция мастера фиксируются одной транзакцией. Повтор сохранения того же черновика не создаёт дубль |
| 13 | Успешное соединение не сбрасывало сетевой backoff | Успех сбрасывает только сетевые счётчики, сохраняя паузы и ограничения аккаунта |
| 14 | Старый подтверждённый JOIN мешал повторной проверке восстановленных прав | Повторная ручная проверка получает новое поколение задания; старое подтверждение сохраняется |
| 15 | FloodWait при получении метаданных входящего события только журналировался | Ожидание сохраняется для аккаунта; последующие RPC останавливаются на этот срок |
| 16 | Короткий FloodWait мог перезаписать более длинное ожидание | Все пути обновляют срок через MAX; подтверждена конкуренция входящего и исходящего путей |
| 17 | Ошибка старого шаблона приостанавливала уже исправленную рассылку | Автопауза конфигурационной ошибки ограничена версией задания |
| 18 | При заполненной очереди намерение ответить в ЛС удалялось | Цепочка сохраняется в SQLite без задания; планировщик продолжает её при освобождении места, в том числе после рестарта |
| 19 | Первая пара могла снова занимать весь малый лимит очереди | При заполнении очереди курсор сохраняется на этой паре; следующая обработка начинается со следующей пары. Ожидающие цепочки ЛС получают слот раньше обычной рассылки |

## Проверки

- Полный набор: **203 passed in 25.63 s**, включая **33 новых случая** в `tests/test_audit_regressions.py`.
- Ruff: без замечаний. CLI smoke: SQLite исправна, тихий период соблюдён, реальных операций 0.
- Существующие тесты остановки, смен, неизвестных исходов, доступа посторонних и изоляции live/dry-run сохранены.
- Проверены частичный сбой SQLite при сохранении мастера, повтор сохранения, перенос/удаление аккаунта, повторное добавление, отозванные права и старые кнопки.
- Проверены рестарт цепочки ЛС, ограниченные повторы и продолжение с подтверждённого префикса. Стикер не повторяется. UNKNOWN автоматически не повторяется.
- Проверено заполнение очереди, сохранение ожидающего ЛС, смена аккаунта после известного отказа и отсутствие возвращения к устаревшей цепочке.
- Миграции проверены с существующей схемой, повторный запуск безопасен; сохранены сессии, история и неопределённые попытки.

## Обновление и запуск

1. Остановить прежний процесс. Сохранить резервную копию SQLite и ключ `SESSION_KEY`.
2. Обновить файлы проекта и зависимости: `python -m pip install -e ".[test]"`.
3. Проверить `.env`: прежний ключ шифрования, `ADMIN_IDS`, нужный `DATABASE_PATH` и режим.
4. Выполнить `python -m app migrate`, затем `python -m app check`.
5. Запустить `python main.py` или `python -m app run` по инструкции README.

Миграция **007_audit_recovery** восстанавливает известные зависшие состояния из версии 2.0.5,
освобождает Telegram ID удалённых записей и добавляет квитанции мастера и поколения проверки прав.
История не удаляется. Задания UNKNOWN остаются для ручной сверки.
Не меняйте SESSION_KEY при обновлении: он нужен для чтения существующих сессий.

## Границы проверки

Живые авторизации, реальные массовые отправки и долговременная нагрузка подключённых Telegram-клиентов не запускались.
Docker локально не собирался. Сетевые тайм-ауты после фактической отправки по-прежнему требуют ручной сверки:
единая транзакция между SQLite и Telegram невозможна, поэтому автоматический повтор UNKNOWN запрещён.
Старые пулы прогрева и искусственные диалоги из исходного архива этим исправлением не добавлялись.
