# Подключение, коды входа, пулы и защита — 2.2.4

Проверка выполнена 20 ноября 2026 года. Бот оставлен выключенным. Настоящие запросы кодов, авторизации, подключения аккаунтов, вступления и отправки не выполнялись. Существующие изменения хостинга и рассылок сохранены: исходное состояние локальной папки совпало с текущим `origin/main` (`67b644b`); исправления подготовлены поверх него.

## Что установлено

В локальном `.env` включён `MODE=dry-run`, нет `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. В локальной тестовой SQLite-базе нет аккаунтов, сессий, чатов и заполненных пулов. Три локальных журнала пустые. Поэтому причину прежнего сообщения «Код не отправлен» на другом запуске по этим данным восстановить нельзя. Состояние серверной конфигурации не проверялось.

В `dry-run` настоящий код не запрашивается: используется `00000`. Для настоящего входа нужны `MODE=live`, одна собственная корректная пара API ID/hash, доступ к Telegram и существующий пользовательский аккаунт. Значения настоящих секретов в отчёт не включены.

| Компонент | Реальное поведение |
|---|---|
| Подключение сессий | Telethon подключает сохранённые сессии, проверяет авторизацию, получает входящие обновления; повторное подключение ограничено backoff. Фоновые подключения запрещены первые 24 часа |
| Статус online/offline | В исходном прогреве есть настоящий `account.UpdateStatusRequest`, выбирающий online или offline. Подключённая сессия и постоянно видимый online — разные состояния. Постоянный online не включался |
| Пул чатов рассылок | Таблица `chat_pool`, импорт и управление через раздел чатов, назначения парам и проверка прав |
| Пул каналов/групп прогрева | Отдельная таблица `warmup_channels`, добавление ссылок и удаление через экран «Каналы прогрева» |
| Пул собеседников прогрева | `warmup_partners`, собственные аккаунты выбираются в «Пуле прогрева» |
| Пул API ID/hash | **Отсутствует**. Используется одна пара из `.env`; автоматической смены API и ротации для обхода ограничений нет |

По документации Telegram [способ доставки кода выбирает сервер](https://core.telegram.org/api/auth): код может приходить в уже открытое приложение, SMS, почту или другим поддерживаемым способом. Гарантировать SMS сторонний клиент не может. Смена статуса использует официальный [account.updateStatus](https://core.telegram.org/method/account.updateStatus).

## Исправления

1. Общий ответ «Код не отправлен» заменён безопасными пояснениями: неверная пара API, неверный/заблокированный номер, ограничения запросов, FloodWait, неверный/истёкший код, неверный 2FA-пароль и сеть. Сообщения не включают исходный RPC-запрос и секреты.
2. Убрана запись полного traceback в обработчиках интерфейса: исключение Telethon может содержать исходный запрос с конфиденциальными полями. В диагностике остаются время, компонент и класс ошибки. Получение кода, ввод кода и пароля проверены через настоящий aiogram-dispatcher с подменённым Bot API.
3. Перед входом и импортом проверяется формат API: положительный числовой ID и hash из 32 hex-символов. Это проверка формата; соответствие пары подтверждает только Telegram. Пробелы по краям hash в окружении удаляются.
4. Повторное начало входа с тем же номером использует ещё действующий запрос, без повторного `send_code_request`. После отмены/неопределённого сетевого сбоя действует локальная пауза минимум 60 с. При конкурентных экземплярах резервирование запроса выполняется транзакцией SQLite.
5. FloodWait авторизации сохраняется в SQLite и действует после перезапуска, в том числе при смене номера и вводе 2FA. Более короткое повторное ожидание не уменьшает уже установленную паузу. Для `PHONE_NUMBER_FLOOD` введена дополнительная локальная пауза 1 час; это консервативная пауза приложения, а не обещание, что серверное ограничение истечёт ровно через час.
6. Номер в ключе ожидания заменён HMAC с `SESSION_KEY`: открытые номера, коды, пароли и `phone_code_hash` не сохраняются в таблице настроек. Обычные сессии и номера продолжают храниться через Fernet.
7. Неверный код/пароль сохраняет текущий процесс входа и не запускает новый запрос. Неподдерживаемый ответ авторизации, регистрация нового аккаунта, бот и отсутствие `phone_code_hash` не сохраняются как успешная пользовательская сессия. Процессы импорта и входа по телефону не смешиваются.
8. В карточке аккаунта показано фактическое состояние соединения без вызова сети при открытии экрана. В настройках показаны тестовый/live-режим и состояние API-пары; API hash не отображается. В подсказке кода указан фактический способ доставки из ответа Telegram.

## Что требует реального сервера

Реальная доставка кода и видимость online другими пользователями не проверены. Обновлённая версия покажет конкретную причину следующей неудачной попытки; предыдущая ошибка по пустым локальным журналам не устанавливается. Автоматического запроса настоящего кода при проверке или обновлении нет.

Ключи из `.env` не зашифрованы самим `.env`: файл и `SESSION_KEY` должны быть доступны только владельцу процесса. Шифрование сессии не защищает от человека, получившего и базу, и ключ. Доступ к боту ограничивается `ADMIN_IDS` в личном чате; защита не даёт гарантии от ограничений/блокировок со стороны Telegram. Использовать нужно свои API-реквизиты и аккаунты. Ранее раскрытые вне защищённого хранилища токены следует заменить.

Новых настроек или обязательного изменения `.env` для тестового режима нет. Схема сохраняется на уровне 012 из текущей версии проекта; новая миграция для этих исправлений не нужна. Для самостоятельного запуска после настройки сервера:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m app smoke
# Только для самостоятельного включения с проверенными настройками:
.\.venv\Scripts\python.exe -m app run
```

Инструкция установки, Docker и параметры окружения — в [README](../README.md). При обновлении сохраняйте действующие `.env`, `SESSION_KEY` и каталог `data`; запуск нового `run` параллельно старому запрещён.
