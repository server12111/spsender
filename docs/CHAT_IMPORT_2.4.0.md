# Импорт чатов — 2.4.0

## Что исправлено

Раньше синтаксис `@username` распознавался, но импорт немедленно обращался к Telegram для каждого имени. При отсутствии аккаунта после тихого периода корректные чаты отклонялись. Поэтому список из 227 чатов мог целиком попасть в ошибки.

Теперь в live-режиме список сохраняется в SQLite без сетевых запросов. Поддерживаются `@username`, username без `@`, ссылки `t.me` / `telegram.me`, приглашения и ссылки на темы. Числовой ID вводить не требуется. Ссылки и имена одного публичного чата приводятся к одному виду; повторный импорт не создаёт вторую запись для той же ссылки и темы.

В «Пуле чатов» сразу видны сохранённые чаты, включая ожидающие проверки. Работают карточки, поиск, фильтр статуса, страницы и удаление. Статистика учитывает сохранённые чаты. После успешной фоновой проверки чат автоматически попадает в обычное распределение между парами. При этом сохраняются подтверждённые права публикации, вступления и приветствий. Разные ссылки на один Telegram-чат объединяются после проверки; темы остаются отдельными.

## Проверка и ограничения

- Один отдельный цикл worker обрабатывает последовательно не более четырёх чатов за проход; меньший настроенный размер пакета также соблюдается. Используются общий бюджет Telegram RPC и блокировка аккаунта. Медленная проверка не останавливает подключение других аккаунтов, планировщик и обработку рассылок.
- Без доступного аккаунта список остаётся сохранённым, попытки не расходуются. Сохраняются тихий период 24 часа, пауза аккаунта и рассылки, FloodWait, задержки переподключения и блокировка аккаунта с неизвестным результатом отправки.
- Проверка читает данные чата. Она не отправляет сообщения и не вступает в чат. Вступление и проверка возможности публикации остаются в существующем механизме подготовки, с подтверждёнными разрешениями.
- Для закрытого приглашения, по которому Telegram не предоставляет чат без членства, сохраняется карточка с причиной и кнопкой повторной проверки. Ввод числового ID не предлагается. Пользователи и боты не допускаются в рассылку как чаты.
- FloodWait сохраняется для аккаунта и останавливает текущий пакет. Потеря авторизации, заморозка и ограничения используют существующие критические уведомления владельцу.
- Временные ошибки повторяются с увеличением задержки в пределах настроенного числа повторов. Затем чат остаётся в пуле со статусом «Нужна проверка»; можно исправить причину и нажать «Повторить проверку». Повторная загрузка того же списка не сбрасывает исчерпанные попытки.
- Задания имеют сохраняемую блокировку на 180 секунд и уникальный идентификатор попытки. После аварии проверка может продолжиться; поздний результат старого процесса не восстанавливает удалённый чат и не перезаписывает новую попытку. Проверенные отправки не повторяются: этот механизм вообще не отправляет сообщения.
- В диагностике используются идентификаторы аккаунта/задания и код причины; содержимое исключений и секреты не записываются.

## Обновление на Bothost

1. Обновить проект из `main` репозитория `server12111/spsender` и пересобрать контейнер.
2. Для хранения оставить `DATA_DIR=/app/data`; `DATABASE_PATH` в настройках сервера не нужен. Сохранить прежний `SESSION_KEY`.
3. При запуске автоматически применяется миграция 014. Она добавляет таблицу ожидающих чатов и индексы, не пересоздаёт таблицы аккаунтов, сессий и чатов.
4. Один раз заново импортировать строки, которые прежняя версия показала как ошибки: тогда они не были сохранены. После успешного импорта повторно загружать их при перезапуске не требуется.

## Автоматические проверки

Полный итоговый прогон: **518 тестов**; дополнительные 27 проверок импорта включены в общее число. Воспроизводимые результаты: [JUnit](chat-import-test-results.xml). Ruff и `python -m app smoke` также проверены. Все тесты используют временные базы и имитацию Telegram; pytest запрещает внешние сетевые соединения.

Новые сценарии включают импорт 227 имён без аккаунтов и сетевых обращений, сохранение после перезапуска, дедупликацию ссылок и тем, права, распределение в пару, ограничение пакета, FloodWait, потерю авторизации, ограниченные повторы, отказ для пользователей/ботов, закрытые приглашения, все блокирующие состояния аккаунта, отмену, удаление во время проверки, истечение блокировки задания и независимость подключения аккаунтов от зависшей проверки.

Нагрузочный сценарий: `python tools/benchmark_chat_import.py` после установки `.[test]`. Он запрещает сетевые соединения, создаёт временную SQLite-базу, импортирует TXT через интерфейс, пересоздаёт Engine и проверяет 1000 чатов имитацией Telegram. Отправок сообщений нет.

Результат на этом Windows-компьютере: **1000 из 1000** чатов сохранены после перезапуска и проверены, **250 пакетов по 4**, **0 дубликатов**, **0 реальных операций Telegram**. Импорт — **5,946 с**, проверка — **25,071 с**, CPU — **3,594 / 16,344 с**, пик памяти процесса — **74,59 МиБ**. [Измерения](chat-import-benchmark.json). Замеры выполнялись одновременно с тестами; это локальные показатели имитации, а не скорость реальных запросов Telegram.

На реальном сервере подключение Telegram и пересборка Bothost в этой проверке не выполнялись. Старые данные не восстанавливались; рабочие `.env`, локальная база, журналы и исходный архив не изменялись.
