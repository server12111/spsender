# API-пул и username чатов — 2.3.0

20 ноября 2026. Добавлены рабочий пул API и расширенный импорт чатов. Настоящие авторизации, запросы кодов, подключения, вступления и отправки при разработке не выполнялись. Бот оставлен выключенным.

## Где находится API-пул

Откройте **Настройки → Пул API ID/hash → Добавить API**. Пришлите свою пару одним сообщением: `API_ID API_HASH`. Для названия используйте `Название | API_ID | API_HASH`. API ID должен быть положительным числом до 2147483647, hash — 32 hex-символа. Сообщение удаляется ботом после обработки. Hash хранится через Fernet с действующим `SESSION_KEY`; в карточках и журнале он не показывается.

Новые аккаунты получают включённую пару с наименьшим количеством закреплений. Её идентификатор передаётся вместе с результатом входа и сохраняется в той же транзакции, что аккаунт/сессия. При импорте сессии используется выбранная пара для создания нового авторизованного клиента. При обычных подключениях и переподключении используется уже закреплённая пара. Добавление других ключей, изменение глобального `.env` или перезапуск не переключает существующую сессию.

Кнопка «Выключить» исключает пару из новых входов. Уже закреплённые аккаунты продолжают использовать её: API-идентичность живой сессии не меняется. Ключи не удаляются и не редактируются поверх существующих закреплений. Повторное добавление той же пары не создаёт дубль; другой hash для существующего API ID отклоняется. Никакого переключения ключей для обхода FloodWait или блокировок нет; общая сохранённая пауза авторизации действует и при наличии нескольких пар.

## Обновление старой базы

Миграция **013_api_pool.sql** добавляет `api_credentials` и `account_api_bindings`, не меняя строки `account_sessions`. При первом запуске сохраняется действующая API-пара из `.env`, старые аккаунты закрепляются за ней. **На первом обновлении оставьте прежние TELEGRAM_API_ID / TELEGRAM_API_HASH в окружении.** Последующие новые ключи добавляйте кнопками.

Бот может запуститься без API в `.env`, чтобы владелец заполнил пул через интерфейс. Если у старой сессии нет закрепления и прежних реквизитов в окружении, она не получает случайную пару из пула: требуется восстановить её прежний API. Такая ситуация диагностируется как ошибка конфигурации `ACCOUNT_API_REQUIRED`, а не как истёкшая авторизация.

Доступ к пулу ограничен `ADMIN_IDS` в личном чате, как и остальное управление. Сохраняйте `SESSION_KEY` и рабочий каталог данных. В локальной рабочей базе миграция не запускалась; она проверена только на временных тестовых базах. На сервере остановите прежний процесс, сделайте резервную копию SQLite, обновите код и выполните миграции перед запуском либо используйте обычный запуск, который применяет миграции при построении Engine.

## Как добавлять чаты

Поддерживаются `my_test_chat`, `@my_test_chat`, `t.me/my_test_chat`, `https://t.me/my_test_chat`, публичные ссылки `telegram.me`, числовые ID, темы и ранее поддерживаемые приглашения. Разделители списка: пробел, перевод строки, запятая или точка с запятой. Можно смешивать форматы в одном сообщении или TXT-файле UTF-8.

Username нормализуется в `@username`, а реальный ID и тип объекта проверяются через Telegram при подтверждении импорта. В пул принимаются группы/каналы, не пользовательские ЛС. Один чат, введённый разными способами, сохраняется один раз по реальному ID/теме. Разрешения публикации подтверждаются на существующем экране импорта.

Для определения реального ID по username/ссылке нужен доступный авторизованный аккаунт после 24 часов тишины. Числовые ID можно добавлять до этого. Импорт не вступает в сообщества и не отправляет сообщения.

## Проверки

Новые сценарии находятся в [test_api_pool.py](../tests/test_api_pool.py). Проверены нормализация имён, смешанный импорт через aiogram, шифрование, сохранение после рестарта, распределение новых аккаунтов, неизменность закрепления, выключение, защита от чужого Telegram ID, удаление сообщения с hash, импорт без глобального API, реальный путь создания транспортного клиента с закреплёнными реквизитами и миграция с сохранением шифротекстов сессий.

Полный результат: **465 passed за 75,18 с**, [JUnit XML](api-pool-test-results.xml), включая 25 новых случаев. Ruff и smoke прошли. Telegram и Bot API подменены, внешние сокеты в pytest заблокированы. Живые ключи/аккаунты и реальная доставка кода этим прогоном не проверялись. Существующие сценарии FloodWait, смен аккаунтов, очередей, автоответов и восстановления входят в общий набор.
