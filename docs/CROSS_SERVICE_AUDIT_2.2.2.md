# Повторная проверка взаимодействия служб — 2.2.2

Проверка от 3 ноября 2026 года. Проверены обработка состояний аккаунта, работа пар при критических ошибках, очереди, порядок подготовки и отправки, история ошибок, восстановление и совместимость адаптеров исходного сервиса. Полный набор автоматических проверок охватывает остальные функции проекта: доступ администратора, кнопки и мастера, импорт/2FA, SQLite и миграции, ЛС, расписание, обмены чатов, подписки, уведомления и статистику.

Бот выключен; настоящие сообщения, вступления и авторизации не выполнялись. Исходный архив не изменялся. Алгоритмы исходных `WarmupService` и `MailingService` не переписывались — изменения внесены в адаптеры и общие службы.

## Исправления

| Найденная проблема | Исправление |
|---|---|
| Критическая ошибка одного аккаунта вызывала исходную остановку «рассылки», которая в адаптере означала всю кампанию | Приостанавливаются аккаунт и его пара; остальные здоровые пары продолжают работу |
| Исходное отключение заменяло `FROZEN`/`RESTRICTED` на `SESSION_EXPIRED` | Сохраняется действующее ограничение, включая текстовый маркер заморозки Telegram |
| Последующая ошибка авторизации либо явное отключение могли стереть ограничение; новая сессия затем возвращала `OK` | Ограничение сохраняется до явного подтверждения владельца. Новая ошибка авторизации всё равно немедленно уведомляет администратора; одинаковые события не дублируются |
| Поздний критический ответ мог изменить состояние уже удалённого аккаунта | Удалённые аккаунты остаются `REMOVED` |
| Удаление, перенос и замена сессии учитывали только общую очередь, пропуская незавершённый RPC прогрева | Проверяются обе системы. Изменение состава пары также учитывает незавершённую операцию партнёра. Пауза и остановка остаются доступны |
| Обработка некорректного чата передавала пустой `account_id` в обязательное поле SQLite | Чат атомарно направляется на проверку с фактическим аккаунтом текущей смены; история не удаляется |
| У уже готовой пары обычная рассылка могла опередить вновь настроенное приветствие | Список целей и последний защитный контроль ждут завершения сохранённого приветствия |
| Перенесённая отправка пропускала сохранённый запрет конкретного аккаунта в конкретном чате | Учитывается `chat_failures`; здоровый партнёр может работать в свою смену, если чат не остановлен целиком |
| Отмена из-за смены состояния учитывалась как ошибка чата и могла включить долгую задержку/проверку SpamBot | Управляющая отмена не считается неудачной отправкой |
| Между защитным чтением и записью задания оставалось окно для остановки или захвата аккаунта другой очередью | Состояние повторно проверяется под блокировкой записи SQLite. Новые часы пары не запускаются после остановки; конфликт очередей завершается управляемой отменой вместо `UNIQUE constraint failed` |
| В адаптере отсутствовал `stop_client`, используемый исходным восстановлением после тайм-аута | Добавлено согласованное отключение с блокировкой аккаунта; при неудаче ссылка на клиент сохраняется для повторной очистки |
| Ошибки с `pair_id`, но без `campaign_id` отсутствовали в истории кампании | Общий журнал сохраняет кампанию пары; миграция **011** восстанавливает эту связь в существующих событиях без удаления или замены записей |
