# ЛС и статус отправки — 2.0.4

При включённом «Первое входящее ЛС» бот отвечает на первое входящее сообщение цепочкой:

1. Стикер Telegram, подобранный по эмодзи (по умолчанию 👋).
2. Короткое приветствие (по умолчанию «Привет!»).
3. Основной шаблон первого ответа, включая его вложение при наличии.

После подтверждения каждой части следующая планируется через 3–4 секунды. Это минимальная пауза: нагрузка, остановка кампании, смены, FloodWait и недоступность Telegram могут отложить отправку. Ожидание хранится в SQLite, воркер не удерживается на `sleep`. Подтверждение сообщения, продвижение последовательности и постановка следующего шага выполняются в одной транзакции.

Функция запускается только в ответ на входящее ЛС. Она не создаёт разговоры между своими аккаунтами. Включение «На каждое входящее ЛС» сохранено как независимая функция: если включены оба сценария, его ответ идёт после трёх частей первого приветствия, тоже с паузой. Последующие входящие используют прежний cooldown (по умолчанию 300 с). Ручные ответы не преобразуются в трёхчастные цепочки.

«Автоответы → рассылка»: переключатель первого ЛС и его основные шаблоны, «Привет в ЛС» для короткой фразы, «Стикер: 👋» для выбора эмодзи. Стикер запрашивается через пользовательский Telegram API и отправляется настоящим стикером; при отсутствии результата рассылка приостанавливается с ошибкой STICKER_UNAVAILABLE, подмена эмодзи не выполняется. Исправьте эмодзи и возобновите рассылку.

Паузы групповых приветствий не менялись. Колонка из промежуточной миграции `005_greeting_spacing` оставлена для совместимости уже созданных БД; миграция `006_dm_sequences` обнуляет её и добавляет отдельные последовательности ЛС. Откатывать существующие файлы БД или удалять историю не требуется.

Сигнал «печатает…» отправляется перед текстом, приветствием, автоответом, ручным ответом и медиа аккаунтов там, где Telegram поддерживает индикатор разговора. Для проверок подключения и вступлений он не отправляется. В каналах-вещателях этот индикатор не показывается. Ответ API ожидается в текущей асинхронной задаче: FloodWait и ошибки авторизации обрабатываются общей системой; фоновые бесконтрольные задачи не создаются. Непосредственно перед сообщением заново проверяются статус кампании, аккаунта, смена и попытка задания.

После перезапуска последовательность продолжает с незавершённого шага. UNKNOWN блокирует её до ручной сверки. При остановке новые части не отправляются; подтверждённый префикс сохраняется. Изменение шаблонов обновляет незавершённый текст, подтверждённый стикер не повторяется. Если оператор отключил сценарий, оставшаяся часть ждёт его включения или явного сброса истории.

Использован подход выбора стикера по эмодзи из исходного `warmup_extras.py`; имитация разговоров и посторонние действия старого прогрева не переносились. Исходный архив только читался.

Проверки выполняются с имитацией Bot API и Telethon без реальных сообщений. **158 тестов успешно, 21,16 с**; результат полного прогона: `dm-sequence-test-results.xml`. Проверены паузы, перезапуск, остановка, UNKNOWN, изменение текста, порядок двух сценариев, отсутствие задержек в группах, отправка стикера и настройка через Telegram-интерфейс. Также прошли Ruff, компиляция, smoke, миграции 001–006, проверка целостности SQLite и зависимостей. Реальная отправка через Telegram не выполнялась. Бот оставлен выключенным.

Первичные источники: [messages.setTyping](https://core.telegram.org/method/messages.setTyping), [messages.getStickers](https://core.telegram.org/method/messages.getStickers).
